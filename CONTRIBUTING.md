# Совместная работа

- Одна задача — один ответственный и короткая ветка от актуальной `main`.
- Имена веток: `feat/<topic>`, `fix/<topic>`, `docs/<topic>`, `chore/<topic>`.
- Изменения через Pull Request; минимум один другой участник проверяет результат.
- PR содержит цель, ссылку на Issue, способ проверки и ограничения.
- Изменения контракта данных/API согласуются с потребителями до реализации.
- Каждый участник отвечает за документацию и подходящие проверки своей части.
- Не добавлять секреты, персональные данные, сырые выгрузки и большие модели в Git.
- В репозитории допустимы небольшие синтетические примеры; происхождение реальных данных документируется отдельно.

## Definition of Ready

У задачи есть цель, границы, результат, зависимости и критерии приёмки.

## Definition of Done

Критерии приёмки выполнены, подходящие проверки пройдены, документация актуальна, PR проверен другим участником, интеграция с соседними компонентами подтверждена, когда применимо.
